# ⚠️ Critical Pitfalls & Points to Remember

## 1. Passing Does Not Equal Committing
Even if an LLM perfectly obeys the 38 rules and generates a flawless PASS report, **never automatically commit its output to the Git worktree**. Conrad is an auditor, not an auto-committer. The agent simply earns the right to have its task tagged as `"Complete"` in `state.jsonl` for user review.

## 2. Do Not Trust LLM Self-Reporting
Do not allow the worker agent to bypass the Conrad gateway just because it generated a `[PASS]` tag. The 4-block report must be generated by the independent Conrad auditor persona, not the worker agent that wrote the code.

## 3. Never Stream Raw Worker Output
You must maintain the mandatory interception architecture. All LLM outputs must be caught in-memory[cite: 3]. If you allow the LLM to stream directly to `stdout`, the user will see unverified AI slop before Conrad has a chance to reject it.

## 4. Respect the Retry Cap
Local LLMs will confidently repeat the exact same mistake. The `DeliveryGateInterceptor` retry mechanism must be capped at 3[cite: 3]. Without this cap, the Podman sandbox will consume 100% of local CPU resources in an infinite generator-verifier loop.
